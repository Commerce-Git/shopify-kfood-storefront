# 구현 배정 — storefront M04 구매 경험 운영 지도

## 목적과 범위

`M04-F001 상품 탐색`과 `M04-F002 장바구니`가 구매자 여정 B01·B02·B05에 어떻게 기여하는지, 실제 코드와 운영 판단에 연결해 한국어로 기록한다. R01, 계약 C02·C03·C06, 인접 모듈 M01·M03·M05의 경계를 명시한다.

수정 대상은 [STOREFRONT_MODULE_OPERATIONS.md](/Users/junseoha/Downloads/blank-seoul-storefront/docs/platform-analysis/STOREFRONT_MODULE_OPERATIONS.md) 한 파일이다. 이 파일은 이미 **추적되지 않은 상태로 존재**하므로 기존 내용을 보존하며 근거를 확인하고 고친다. Gemini는 작업 결과와 수동 조치 사항을 `.agent-bridge/REPORT.md`에 기록한다.

다음 사항을 특히 점검한다.

- 화면 → 컴포넌트·훅 → Shopify·Supabase·브라우저 저장소의 읽기·쓰기 경로와 preview/live 분기.
- 코드 사실, 운영에서 검증된 행동, 제안, 정책 미결정(Q01·Q03·Q05), 미실행 검증을 구분한다. Shopify 게시 상태를 관리자 승인이나 한국 제조 확인의 증거로 취급하지 않는다.
- `/api/stock`의 15초 캐시를 실시간 보장으로 표현하지 않는다. `cartCreate`의 품절·쿠폰 오류 반환과 최종 결제 금액은 실제 연동으로 검증하지 않은 부분으로 표시한다.
- 상품 없는 작가의 공개 여부와 장바구니 백업 삭제는 정책·인접 여정에 영향이 있는 **제안**으로 유지한다. 확정된 변경 규칙처럼 쓰지 않는다.
- 절대 `file:///` 링크를 저장소 내 상대 링크로 바꾸고, 인용한 파일·함수·경로가 실제로 존재하는지 확인한다.
- 변경 영향, 정상·실패 사례, 현재 관측 신호와 제안 지표, 후속 모듈에 재사용할 짧은 기록 템플릿을 포함한다. 약 250줄 이내를 목표로 한다.

## 비목표

앱·테스트·설정·패키지 및 다른 분석 문서는 변경하지 않는다. 어드민 저장소를 열거나 재분석하지 않는다. 사업 정책 결정, 기능 수정, 외부 서비스 호출, SQL·마이그레이션 적용, 배포 및 Git push는 이 배정에 포함하지 않는다.

## 인수 기준

1. 문서만 읽어도 M04의 책임, B01·B02·B05의 진입점, C02·C03·C06의 데이터 경계와 변경 영향을 추적할 수 있다.
2. 문서의 모든 로컬 링크가 현재 작업 루트 안의 실제 파일을 가리킨다. 기존 `FEATURE_MAP.md`를 반복하는 대신 변경·장애 시 확인할 위치와 증상을 제시한다.
3. 관측되지 않은 운영 동작과 미결정 정책을 확정 사실로 서술하지 않는다. 대표 정상·실패 검증에는 조건, 기대 결과, **현재 검증 상태**가 있다.
4. 실제 변경 파일은 운영 지도와 Gemini의 `REPORT.md`뿐이다. 보고서에는 수정 요약, 근거, 미확인 사항, 필요한 수동 조치를 적는다.

## 검증과 테스트 설정 요청

오케스트레이터가 [pipeline.config.json](/Users/junseoha/Downloads/blank-seoul-storefront/.agent-bridge/pipeline.config.json)에 등록된 `typecheck`, `unit`, `lint`, `build`를 독점 실행한다. Gemini에게 명령 실행을 배정하지 않는다. 이 회귀 검사의 통과를 문서의 링크 정확성이나 실제 구매 여정 검증으로 해석하지 않는다. 문서 전용 작업이므로 새 앱 테스트는 필요하지 않다.

**사용자에게 요청하는 설정 변경:** 현재 설정에는 Markdown 문서 검사가 없다. `.agent-bridge/pipeline.config.json`에 네트워크 없이 실행되는 문서 검사 항목을 추가해, 이 파일의 로컬 링크 존재 여부·필수 ID와 절 제목·약 250줄 기준을 확인해 달라. 이 설정과 검사 구현은 이번 Gemini 수정 범위 밖이다. 코드 사실과 정책 표현의 정확성은 독립 검토자가 원본 코드·공통 문서와 대조해야 한다.

## 수동 조치

- **사용자:** 위 문서 검사 항목을 테스트 설정에 추가한다. 추가 전에는 해당 기준의 자동 검증을 미완료로 기록한다.
- **Gemini:** `REPORT.md`에 SQL·Supabase 적용·배포 작업이 필요 없음을 명시한다. Git push가 필요해지면 사용자가 직접 수행할 항목으로 기록한다.
