# 운영 환경·성능·배포 대조

2026-09-24 · 로컬 근거 확인, 운영 콘솔 미접속. 환경변수의 실제 값과 고객 데이터는 읽거나 문서에 요청할 자료가 아니다. 필요한 것은 설정의 존재·환경 분리·지표·버전이다.

## 1. 로컬에서 확인한 것

| 대상 | 사실 | 해석의 한계 |
| --- | --- | --- |
| F 패키지 | Next `16.2.3`, Supabase SDK `^2.103.3` 선언 | 실제 배포 설치 버전·리전 미확인 |
| A 패키지 | Next `16.2.0`, Supabase SDK `^2.101.0` 선언 | 버전 차이가 장애라는 증거는 아님 |
| F Vercel 설정 | `vercel.json`에 `crons: []` | 외부 스케줄러/콘솔 설정은 별도 확인 |
| A GitHub 작업 | fulfillment workflow의 schedule 주석·job `if:false` | 이 workflow는 실행 경로로 의존할 수 없음; 다른 스케줄러 가능 |
| A cron API | auto-pipeline, process-sync-jobs, send-artist-emails 존재 | 호출 주기·마지막 성공·적체 미확인 |
| F cron API | coupon-reminder, send-review-request 존재 | 실제 트리거 미확인 |
| A 동기화 | 프로세스 캐시·DB 큐·claim RPC·워커 리스 코드 존재 | 운영 SQL 적용·중단 복구 미확인 |
| F/A 배포 연결 | `.vercel/project.json` 없음, A `vercel.json` 없음 | 미배포를 뜻하지 않음 |
| Supabase | 두 코드베이스의 테이블·RPC 참조와 여러 경로의 SQL | 같은 운영 프로젝트를 사용하는지와 실제 정의 미확인 |
| agent-bridge | 두 설정 존재, 제공된 실행기는 단일 Git 루트 | 실제 인증·다중 프로젝트 실행은 별도 검증 |

SQL 파일 순서만으로 실제 스키마를 재구성해 확정하지 않는다. 예전 생성 SQL·나중의 권한 회수·새 RPC 버전이 함께 있으므로 실제 정의·권한과 대조해야 한다.

## 3. Disk IO 진단 순서

1. 경고가 실제로 이어지는지, 시간대와 당시 사용자·배치·백업·동기화 활동을 확인한다.
2. 대기 시간·읽기/쓰기량·호출 빈도·DB 메모리/연결·쿼리 통계를 연결한다.
3. PF07의 무범위 조회, 옵션 검색 fallback, 전체 정산 집계와 운영 상위 쿼리가 일치하는지 확인한다.
4. 영향 큰 쿼리부터 범위 축소·페이지네이션·인덱스·집계·배치 속도·캐시를 비교하고 실제 측정한다.
5. 지속 처리량이 사양을 넘으면 컴퓨트/디스크·메모리·연결 용량 변경과 비용을 비교한다. 코드를 읽은 것만으로 경고 해결을 선언하지 않는다.

확정한 관측 지표·원인·개선 전후 수치가 아직 없으므로 특정 증설 상품이나 사양을 추천하지 않는다.

## 4. 배포·DB 변경의 운영 원칙

- 먼저 스키마를 호환 가능하게 추가하고, 새 코드를 배포·관측한 후 구형 경로를 제거하는 순서를 검토한다. 구체적 순서는 변경마다 확정한다.
- 프론트와 어드민의 배포 시차 중에도 기존 입력·출력이 동작해야 한다.
- SQL 파일 작성 시 예상 영향·잠금·백업·검증·되돌림/보정 절차를 함께 적는다. 실제 SQL 적용·Git push는 사용자 수동.
- 완료 증거에는 DB 적용 확인, 양쪽 배포 SHA, 시험 시각·환경을 포함한다. 코드 커밋만으로 운영 수정 완료를 표시하지 않는다.

## 5. 성능 목표를 시험으로 바꾸기

20,000명은 작가 10,000명과 방문자/구매자 10,000명의 동시 세션 목표다. 등록 계정 수나 초당 20,000개 DB 요청으로 바꾸지 않는다.

시험 전에 사용자 역할별 행동 비율·요청 간격·페이지당 API 호출·캐시 상태·상품/주문 누적량·작가별 편차·리전·모바일 조건을 정한다. 1,000→5,000→20,000 세션 단계 시험, 장시간 유지, 드롭 직후 급증, 배치 병행, 장애 후 회복을 계획한다. 단계별 처리량·오류·p95/p99·IO·정합성·큐 지연·비용을 함께 기록한다.

현재 동시 이용 수용량과 월 운영 비용은 산정할 근거가 부족하다. 공식 서비스 한도·요금·버전은 실제 배포/계정 정보를 확보한 시점에 공식 자료로 다시 확인한다.
