# 사용자 여정과 플랫폼 기능 평가

2026-09-24 · 2차 로컬 분석 v0.1 · 목표 원본: [PROJECT_DIRECTION](PROJECT_DIRECTION.md)

구매자·작가·물류 담당자·운영자의 전체 흐름을 코드의 기능 단위와 연결한다. 추가로 발견한 외부 공급업체 역할도 포함한다. 기능별 실제 경로는 [FEATURE_MAP](FEATURE_MAP.md), 데이터 책임과 모듈 간 계약은 [DATA_AND_FLOWS](DATA_AND_FLOWS.md)에 기록한다.

**판정 범위:** 화면·hook·API·처리 함수의 정적 연결을 조사했다. 브라우저 실행, 실제 계정, DB 적용 상태, 결제·배송·지급 통합 시험은 이번 분석에서 수행하지 않았다. 아래 인수 기준은 기존 요구사항을 구체화한 검증 초안이며, 정책이 필요한 항목은 질문 번호를 붙였다. 모든 기능을 출시 필수로 확정한 것은 아니다.

## 1. 역할별 목표

| 역할 | 달성할 결과 | 연결 요구사항 | 목표를 확인할 대표 증거 |
| --- | --- | --- | --- |
| 구매자 | 구매 가능한 작품을 찾고, 주문과 배송·취소·반품 진행을 이해한다 | R01/R05/R10/R12, A10/A12 | 실제 구매 여정, 부분 배송·환불 표시, 모바일·실패 복구 시험 |
| 작가 | 본인 역량에 맞는 판매량과 상품 조건을 정하고, 주문을 이행하며 정산 근거를 확인한다 | R02/R04/R06/R07, A01/A04 | 본인 데이터 격리, 상품 변경 이력, 납기와 정산 대조 |
| 물류 담당자 | 실제 받은 물건을 정확히 기록하고, 가능한 주문을 합포장 또는 분리 출고한다 | R04/R05/R12, A02/A03 | 라인별 입출고 수량·창고·송장 대조, 재시도·예외 처리 시험 |
| 운영자 | 계정·상품·주문·정산 예외를 처리하고 서비스 상태와 비용을 관리한다 | R03/R08/R09/R11, A05–A11 | 승인·정정 이력, 지급 대조, 운영 지표·복구·배포 기록 |
| 공급업체 — 코드에서 발견 | 발주 요청을 확인하고 승인/거절·발송을 기록한다 | M03 하위 기능; 출시 포함 여부 Q04 | 발주 품목·수량·토큰 접근·입고 결과 대조 |

현재 사업 방향은 한국 제조 상품이며 K-Food는 통관·작가 모집의 어려움 때문에 보류한다([D015/D016](PROJECT_DIRECTION.md)). 우선 상품군·판매 시장·한국 제조 확인 기준·출시 형태·운영 예산은 추가 구체화가 필요하다. 기능 수와 문서 수를 사업 목표의 달성 지표로 사용하지 않는다.

## 8. 이번 조사 결과의 범위

- 두 저장소의 페이지 45개·라우트 파일 150개를 M01–M12에 주관 모듈 기준으로 분류했다. 파일 전체의 모든 기능·메서드·보안을 검증했다는 뜻은 아니다.
- 화면·hook의 API 문자열 참조와 진입점의 DB/RPC 참조, 코드 해시를 [journey-evidence.json](journey-evidence.json)에 저장했다. 동적 URL, 간접 호출, 별도 스크립트·실제 트리거는 이 추출만으로 판정하지 않는다.
- 기존 `inventory.json`에 수집된 1,062개 파일의 해시를 대조한 결과 이번 추가 조사 시점에 변경·누락은 없었다. 따라서 과거 로컬 검사 결과와 동일한 소스 기준선이며, 이번에 그 테스트를 다시 실행한 것은 아니다.
- 원래 수집한 SQL·스크립트 목록은 [SOURCE_INVENTORY](SOURCE_INVENTORY.md)에 유지한다. 이번 역할별 여정은 앱 진입점과 대표 처리 경로를 중심으로 연결했다.
- 새 분석에서 드러난 주요 범위는 입점 활성화와 상품 승인 분리, preview/live 운영 모드, 벤더 발주 모델, 공개 작가 프로필, 문의·성장 기능, 내부 운영 도구다. 현재 동작을 사업 정책으로 확정하지 않았다.

다음 단계는 Q01을 기준으로 출시 범위를 논의하면서 J01–J07의 미확인 연결을 보완하는 것이다. 운영 접근 없이 가능한 코드 추적은 계속할 수 있다. 개별 결함 수정 순서는 전체 모듈 평가와 정책 의존성을 반영해 별도로 결정한다.
